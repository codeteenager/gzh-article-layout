# 产品使用指南

## 这是什么

`gzh-article-layout` 是一个面向 AI Agent 的微信公众号文章排版引擎：输入 Markdown，输出可复制到公众号编辑器的 HTML 正文。

它解决的不是“写文章”，而是把已经完成的内容稳定地转换成一套可复用、可检查、可回滚的视觉排版：

- 统一标题、正文、引用、代码、列表、图片和结尾 CTA 的层级；
- 从 15 套内置色系和 3 种章节版式中快速选择；
- 处理公众号容易过滤的 HTML/CSS；
- 在交付前用脚本检查结构、标点和内容是否遗漏。

> 目标是提高粘贴成功率和排版一致性，不承诺所有微信客户端、深色模式和编辑器版本都达到网页像素级一致。

## 用户最终拿到什么

一次完整交付应包含：

1. **正文 HTML**：只有公众号正文片段，不包含 `html/head/body/script/style` 外壳；
2. **预览 HTML**：可在浏览器打开并点击“复制到公众号”；
3. **选择说明**：使用了哪个色系、哪个版式，以及为什么适合文章；
4. **校验结果**：`validate_gzh_html.py` 的 ERROR/WARNING 结果；
5. **待补项清单**：例如作者信息、二维码、图片或视频仍需用户提供。

## 最短使用路径

普通 Agent 排版采用“读取组件库 → AI 分析结构与语义增强 → AI 装配 HTML → Python 校验 → 包装预览”的流程。AI 使用所选主题的完整组件定义，不凭记忆重写样式。离线渲染器保留给明确要求脚本转换、批量处理及工程回归的场景；它按 Markdown 标记确定性转换，不负责主动提取语义关键词。两条路径不保证 HTML 字节级相同，交付前均须校验和检查显示。

### 给 Agent

```text
把 article.md 排成微信公众号文章。
生成正文 HTML、预览页，并完成校验。
作者：Jacob
简介：关注 AI 产品与工程实践
二维码：https://example.com/my-qr.png
```

未指定主题和版式时，直接使用 **【墨规】· 翡翠林木（`emerald + ruler`）**，无需确认。仅指定主题时使用该主题登记的默认版式；仅指定版式时使用 `emerald` 色系。“直接排”或“一键排版”会跳过结构确认，使用相同的默认参数。需要推荐时请明确说“推荐主题”。

### 用离线脚本

```bash
python3 scripts/render_stitch_article.py article.md \
  --theme emerald \
  --layout ruler \
  --author "Jacob" \
  --bio "关注 AI 产品与工程实践" \
  --qr-url "https://example.com/my-qr.png" \
  --output article_排版.html

python3 scripts/validate_gzh_html.py article_排版.html
python3 scripts/wrap_preview.py article_排版.html
```

然后打开生成的 `article_排版_预览.html`，点击“复制到公众号”，再粘贴到公众号编辑器。

## 三个选择先说清楚

### 1. 色系：决定整篇文章的品牌气质

色系不是章节结构。比如 `mineral-blue + overprint` 表示“群青色系 + 浮光版式”，不会只改变章节标题。

| 内容倾向 | 推荐 |
|---|---|
| 工程、教程、工具盘点 | `emerald` |
| AI、系统、硬核科技 | `mineral-blue` |
| 商业、人物、品牌故事 | `bamboo-teal` |
| 公告、里程碑、典藏内容 | `vermilion-seal` |
| 文学、摄影、极简长文 | `monochrome-zen` |
| 空间、建筑、留白随笔 | `frost-slate` |

完整列表以 [`references/theme-index.md`](../references/theme-index.md) 为准。

### 2. 版式：决定章节标题的阅读节奏

- `ruler` / 墨规：小型编号徽标，适合教程、工程文和步骤型内容；
- `overprint` / 浮光：低透明大数字，适合特刊、人物和观点长文；
- `pure` / 素墨：不强塞章节编号，适合文学、随笔和严肃报告。

### 3. 身份信息：决定结尾名片是否完整

- 默认不传作者参数、不显示名片，不设置默认作者和简介；
- 仅明确要求名片时提供 `--author`，简介按实际内容提供 `--bio`；
- 提供 `--qr-url`：恢复完整二维码名片；
- 不提供二维码：生成无二维码名片，不冒用设计稿示例二维码；
- 原文已有“我是……”或互动文案：默认保留署名为正文；显式传入同名作者时才合并为名片，互动提示保持末尾一处。

## 输入约定

推荐输入为结构清楚的 Markdown：

```markdown
# 文章标题

> 开头引言或摘要

## 第一章

正文、**重点**、==高亮==、++关键词++。

### 小节标题

```python
print("代码")
```
```

支持：标题、引用、加粗、高亮、下划线、删除线、代码块、图片/GIF、列表、任务列表、表格、链接、脚注、details 和 `::: warning/info/tip/quote` 扩展块。

DOCX、PDF、TXT 等非 Markdown 输入，应先按 [`references/format-normalize.md`](../references/format-normalize.md) 归一化，再排版。

## 交付前检查

- [ ] 文章标题、章节标题和正文没有被设计稿示例文案替换；
- [ ] 作者、简介和二维码是用户自己的，或明确保留了占位；
- [ ] 图片 URL 可访问，图片有 alt 时才生成图注；
- [ ] 代码块没有被当作普通段落，缩进没有丢失；
- [ ] 原文已有署名和 CTA 时没有重复生成；
- [ ] 正文 HTML 通过 `validate_gzh_html.py`；
- [ ] 浏览器预览后检查手机宽度、长标题、长链接和长代码行；
- [ ] 首次发布前在目标公众号编辑器中实际粘贴一次。

## 设计稿与公众号的边界

来源原稿是网页设计稿，当前项目对它做了适配：

| 原稿能力 | 当前产品行为 |
|---|---|
| Tailwind、外部字体、网页工具栏 | 转为离线内联样式和系统字体回退 |
| 绝对定位、响应式媒体查询 | 转为公众号安全的文档流和固定安全宽度 |
| Material Symbols 字体图标 | 转为内联 SVG 图标 |
| 二维码示例素材 | 仅在画廊/对照页展示；正式文章由用户传入二维码 |
| 网页按钮、折叠、分享动作 | 保留视觉层级，不伪装成可执行网页交互 |

查看 [同文同色对照页](gallery/comparison.html) 可以区分“原稿结构”和“公众号兼容差异”。

## 常见问题

### 为什么生成后和来源设计稿不是完全一样？

因为公众号会过滤外部 CSS、脚本、类名、定位和部分响应式规则。项目优先保留信息层级、色板、间距、名片、分享区和章节识别，而不是把网页外壳原样粘贴。

### 为什么二维码不显示？

设计稿示例二维码需要原站的登录态。正式生成不要依赖它，请传入自己的 `--qr-url`；没有二维码时，系统会省略二维码图片但保留不破坏布局的名片结构。

### 为什么建议先看画廊？

画廊用于选风格，不是最终文章编辑器。正式文章仍然以用户 Markdown 为唯一内容来源，并且需要使用真实作者信息、真实图片和真实二维码。

## 文末互动与关注转化

点赞、收藏、分享作为可选互动邀请，不等同于关注入口。默认文案为“有用就点个赞，收藏方便回看，也欢迎分享给需要的朋友。”保留来源设计的圆角互动卡片、顶部图标及“点赞／收藏／分享”图标动作行，以静态富文本展示，不能触发微信原生操作，不要求三连。真实作者名片及用户提供的关注二维码负责身份展示与关注引导；缺失信息不补造。自定义互动文案在卡片内只渲染一次，保留设计的动作行，正文中的“转发”不自动改写。这是产品设计约定，不代表已通过微信官方审核或所有客户端验证。
